    Advanced Options
    Extra Request Header

    Leave empty unless the hub has a claim-header binding (require_claim_header); a hub without one ignores it. With the default on_missing reject, a missing or repeated header gets 400, a missing or mismatched claim 403, an unusable claim 401. Example: header Group-ID, value red, for a token whose groups claim holds red. See claim bindings.

    Sent with hub requests when both fields are set.

    Hub Key & New Tokens

    The fixture-key examples and copy tools are shown only in playground mode (published, insecure test keys), which is off or could not be checked. With the Caddy build, mint a token with caddy mercure-token.

    Which key does the hub verify tokens with?

    Follows the token in the JWT field: HS… selects HMAC, RS… or PS… selects RSA. Switching it does not change the token.

    These examples cover HS256 and RS256. The hub also accepts the other HMAC and RSA algorithms, ECDSA (ES…) and EdDSA: see issuer blocks.

    Mint a token

    The hub already filled in an all-access token. Mint your own to test narrower grants or extra claims such as groups.

    Signed with the RS256 fixture private key (the hub verifies with the matching public key):

    --dev fills in iss, aud and the expiry (2100); --aud sets another audience. Paste the printed token into the JWT field.

    Publishes on one topic, subscribes to a pattern and carries a subscriber payload:

    --dev fills in iss, aud, the signing key ($MERCURE_PUBLISHER_JWT_KEY, else the default development secret) and the expiry (2100); --aud sets another audience. Paste the printed token into the JWT field.

    Other claims (jwt.io)
